# 异常处理

程序运行时会遇到无法继续的情况：文件不存在、输入格式不对、网络断开。异常处理让程序有机会捕获错误、给出提示，而不是直接崩溃。

## 试 / 捕获 / 最终

```csay 试捕获最终
试 {
    抛出 "演示错误"          // 模拟一段可能失败的代码
} 捕获 (异常 错) {
    打印($"捕获到：{错.信息}") // 捕获到：演示错误
} 最终 {
    打印("无论如何都会执行")   // 一定会执行
}
```

三个部分的含义：

- `试 { }`：放可能出错的代码；
- `捕获 (异常 错) { }`：出错时执行，`错` 是异常对象；
- `最终 { }`：不管有没有出错都执行，适合清理资源。

`错.信息` 是错误说明文本。

## 抛出异常

自己的代码也可以用 `抛出` 主动报错：

```csay 主动抛出
试 {
    抛出 "年龄不能是负数";
} 捕获 (异常 错) {
    打印($"捕获到：{错.信息}");
}
```

`抛出` 后面可以是文本，也可以是一个异常值。程序里更常见的做法是把错误往上抛，让调用方决定怎么处理。

## 异常类型与多捕获

内建了几种异常：`参数异常`、`状态异常`、`文件异常`、`越界异常`、`格式异常`。`异常` 是所有异常的通用类型，可以捕获任意一种。

一个 `试` 可以写多个 `捕获`，从上到下匹配：

```csay 异常类型
试 {
    抛出 文件异常("配置不存在");
} 捕获 (参数异常 错) {
    打印($"参数错误：{错.信息}");
} 捕获 (文件异常 错) {
    打印($"文件错误：{错.类型}");   // 文件错误：文件异常
} 捕获 (异常 错) {
    打印($"其他错误：{错.信息}");
}
```

`错.信息` 是错误文本，`错.类型` 是异常类型名。没有匹配的异常会在执行 `最终` 后继续向外抛出。

## 没有捕获会怎样

如果异常没有被任何 `捕获` 接住，程序会打印“未处理的异常：……”并以非零退出码结束。命令行脚本可以据此判断失败。后面的代码不会再执行。

## 在函数里抛出

函数可以把异常交给调用方处理：

```csay 函数抛出
试 {
    打印(安全相除(10, 2))   // 5
    打印(安全相除(10, 0))   // 抛出异常
} 捕获 (异常 错) {
    打印($"捕获：{错.信息}")
}

小数 安全相除(整数 甲, 整数 乙) {
    若 (乙 == 0) {
        抛出 "除数不能为 0";
    }
    返回 (甲 + 0.0) / 乙;
}
```

第二个调用抛出的异常被顶层捕获了。异常会沿着调用链向上找最近的一个 `捕获`。

## 使用：自动关闭

有些资源用完必须关闭。`使用` 会在离开块时自动调用对象的 `关闭()`，即使块里抛出异常也会调用：

```csay 使用
使用 (新 门()) {
    打印("正常离开");
}

试 {
    使用 (新 门()) {
        抛出 "门里出错了";
    }
} 捕获 (异常 错) {
    打印(错.信息);
}

类 门 {
    公开 门() { }
    公开 无 关闭() {
        打印("关门");
    }
}
```

输出顺序是：

```text
正常离开
关门
关门
门里出错了
```

第二次 `关门` 发生在异常向外抛出之前。`使用` 的目标必须是类对象，类里要有无参的 `关闭()` 方法。

为了确保关闭一定发生，`使用` 块里不能写 `返回`、`跳出` 或 `跳过`。需要提前结束时，把判断移到块外。

## 什么时候用异常

异常适合**真正的异常情况**，不是普通的流程控制：

- 文件不存在、没有权限；
- 用户输入完全不符合格式；
- 程序内部状态被破坏。

“分数不及格”“列表为空”“找不到记录”这类可预期的情况，用 `若` 或返回值表示更清楚。异常只处理“没法继续正常执行”的问题。

## 小结

- `试 { } 捕获 (异常 错) { } 最终 { }` 是完整结构。
- `捕获` 可以写多个，具体异常类型按种类匹配，`异常` 捕获全部。
- `错.信息` 是错误文本，`错.类型` 是异常类型名。
- `抛出 "..."` 主动抛异常，也可以抛出具体异常对象。
- 未捕获的异常会终止程序并返回非零退出码。
- `使用 (资源) { }` 会在离开块时调用 `关闭()`，异常路径也会关闭。
- 异常会沿调用链向上传播。
- 异常只用于真正的错误，不要拿它代替普通分支。
