# 区域与内存

Csay 没有垃圾回收。普通对象创建后会一直占着内存，直到进程结束。`区域 { }` 用来给一批临时数据划定生命周期：进入块时分配，离开块时整块回收。

## 区域的基本用法

```csay 区域回收
打印("开始")
对于 (整数 i = 1; i <= 3; i++) {
    区域 {
        文本 行 = $"第 {i} 轮" + "（临时数据）"
        打印(行)   // 每轮结束，行占用的内存被整块回收
    }
}
打印("结束")
```

`行` 在 `区域` 块里拼接、打印。离开右花括号时，这一块里分配的文本、列表、表、类对象会一起释放，不需要逐个 `free`。

## 区域和普通块的区别

普通的 `{ }` 只影响变量作用域，不负责回收内存。`区域 { }` 额外做了一件事：块结束时释放这一层的堆分配。

```csay 区域里建列表
区域 {
    列表<整数> 数 = 新 列表<整数>()
    对于 (整数 i = 1; i <= 1000; i++) {
        数.追加(i)
    }
    打印($"区域内的列表有 {数.数量} 个元素")  // 1000
}
打印("区域已结束")
```

这个列表有 1000 个元素，离开区域后整块回收，不会随着循环次数增加而泄漏。

## 返回文本会自动复制

区域里拼出来的文本可以安全地返回。编译器会把结果复制到区域外：

```csay 返回文本
文本 拼接(文本 甲, 文本 乙) {
    区域 {
        文本 结果 = 甲 + "-" + 乙;
        返回 结果;
    }
}

打印(拼接("a", "b"));
```

文本是连续字节，复制一次就干净了。列表、表、类对象不行：它们内部可能还引用区域里的其他对象，编译器无法安全地整体拷贝，因此从区域里返回这些类型会直接报错。

```csay-static 编译不过的写法
列表<整数> 造列表() {
    区域 {
        列表<整数> 数 = 新 列表<整数>();
        数.追加(1);
        返回 数;
    }
}
```

编译这段代码会得到“区域块里不能返回列表”的错误：如果允许返回，区域一回收，返回的列表就指向已经释放的内存，程序会在别处崩溃，而且很难查。

## 提前离开区域

`返回`、`跳出`、`跳过` 都可以写在区域里。编译器会在跳转前插入释放代码，从内到外逐层退出区域：

```csay 区域里的返回
整数 首个正数(整数[] 数) {
    区域 {
        遍历 (整数 x 在 数) {
            若 (x > 0) {
                返回 x      // 返回前先释放区域
            }
        }
    }
    返回 -1
}

整数[] 甲 = [-3, -1, 7, 9]
打印(首个正数(甲))  // 7
```

`跳出` 只结束当前循环体内的区域；循环外的区域不受影响。写代码时不需要手动补释放，编译器会处理。

## 手动带出文本：保留

个别情况下，文本是在区域里拼出来的，但你想在区域外继续使用，可以调用 `保留()` 显式复制：

```csay 保留
区域 {
    文本 局部 = "局部" + "字符串";
    文本 带出 = 保留(局部);
    打印($"区域内：{带出}");
}
打印("完成");
```

`保留()` 只接受文本。列表、表、类对象仍然不能通过它带出区域。

## 什么时候该用区域

- 循环里反复创建临时文本、列表、表；
- 一次请求/一轮计算结束后可以整批丢弃的中间数据；
- 明确知道生命周期、不想逐个释放的对象。

如果对象要在整个程序里长期存在，不要放进区域，否则块一结束对象就没了。区域是一种**手动生命周期管理**，用对了很省事，用错了会制造悬垂引用。

## 小结

- Csay 没有 GC，普通堆分配不会自动回收。
- `区域 { }` 在离开块时整块释放块内的堆分配。
- 文本可以从区域返回，编译器会自动复制。
- 列表、表、类对象不能从区域返回，会编译报错。
- `返回`、`跳出`、`跳过` 离开区域时，编译器自动补释放。
- `保留()` 可以手动把文本复制到区域外。
- 闭包捕获的环境在堆上分配，同样不会自动释放；大量长期存活的闭包会持续占用内存。
