# 项目与打包

## 项目文件

项目目录用 `项目.csayproj` 描述入口、输出和可选的多目标：

```json
{
  "name": "多文件示例",
  "entry": "主.csay",
  "output": "多文件示例",
  "version": "0.2.0",
  "exclude": ["生成/**", "资料/**"],
  "resources": ["资料", "配置.json"],
  "dependencies": ["../公共库", "工具"],
  "beforeBuild": "node 生成版本.js",
  "afterBuild": "node 复制产物.js",
  "targets": [
    { "name": "主程序", "entry": "主.csay", "output": "主程序" },
    { "name": "工具", "entry": "工具入口.csay", "output": "工具" }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `name` | 项目名称 |
| `entry` | 入口文件，相对项目目录，必须在目录内且存在 |
| `output` | 输出文件名，不含 `.exe`；未设置时取目录名 |
| `version` | 打包版本号 |
| `exclude` | 可选，打包时不复制到 `源码/` 的路径或 glob；匹配项目目录内的相对路径 |
| `resources` | 可选，运行时需要的文件或目录；CLI 构建时复制到 `build/`，打包时复制到每个目标的根目录。路径必须在项目内，不能是 `build` |
| `dependencies` | 可选，依赖的项目目录数组，相对当前项目目录；按顺序先构建或检查这些项目，支持 `..` 指向外部目录 |
| `beforeBuild` | 可选，构建前执行的命令；工作目录是项目目录 |
| `afterBuild` | 可选，构建成功后执行的命令；工作目录是项目目录 |
| `targets` | 可选，多目标数组；每项含 `name`、`entry`、`output`。设置后 `entry`/`output` 取第一项，CLI 和打包按全部目标处理 |

编辑器顶栏“项目”、侧栏项目条和空白处右键都能打开项目设置。项目设置里的“资源文件”和“依赖项目”用逗号或换行分隔；“多目标”每行写 `名称|入口=输出`，省略名称时用输出名；留空则只使用上面的入口和输出。也可以右键 `项目.csayproj` 直接编辑。

## 多文件

入口文件用 `引 模块名;` 引入同目录或其他可解析路径的 `.csay` 文件：

```text 入口
引 工具;

打印(平方(7));
```

被引文件只放类型声明和函数，不能有顶层可执行语句：

```csay 工具
整数 平方(整数 x) {
    返回 x * x;
}
```

`引` 会递归加载依赖；编译器检查被引文件是否混入可执行语句。

## 命令行构建

```bash
csay --project examples/多文件
csay --project examples/多文件 --build
csay --project 多目标项目 --check
```

单目标项目产物在 `build/` 下，文件名取 `output`。多目标项目会依次编译每个目标，产物为 `build/<每个 output>.exe`；多目标只编译、不自动运行。`--format`、`--print`、`--tokens` 会逐个目标处理，`--format` 直接重写各目标的入口文件。

## 依赖项目

`dependencies` 按声明顺序先处理依赖项目，再处理当前项目：

```json
{
  "entry": "主.csay",
  "output": "主程序",
  "dependencies": ["../公共库", "工具"]
}
```

- `--check` 会依次检查依赖项目和当前项目；构建或运行时先构建依赖项目，再构建当前项目。
- 依赖项目可以使用 `..` 指向当前项目目录之外，但必须包含 `项目.csayproj`。
- 每个依赖项目使用独立构建目录 `build/deps/<目录名>/`，不会和当前项目的输出名冲突。
- 依赖可以递归；发现循环依赖会报错并停止。
- 依赖项目的 `beforeBuild`、`afterBuild`、资源复制和多目标规则与单独构建时一致。

## 构建前与构建后命令

`beforeBuild` 在复制资源、编译之前执行；`afterBuild` 在所有目标编译成功后执行一次。命令用系统 shell 运行，工作目录是项目目录，失败会中止后续步骤：

```json
{
  "entry": "主.csay",
  "output": "示例",
  "beforeBuild": "node 生成版本.js",
  "afterBuild": "node 复制产物.js"
}
```

`--check`、`--format`、`--print`、`--tokens` 只做检查或输出，不执行这两个命令。编辑器点击“打包”时也会执行，然后才生成压缩包；直接运行当前文件属于单文件构建，不读取项目命令。

## 打包

编辑器点击“打包”会：

1. 编译每个目标及其 `引` 依赖；
2. 单目标把 exe、项目文件、未被 `exclude` 排除的源文件、`resources` 和 `README.txt` 放进暂存目录；多目标按目标名建子目录，每个目标都有自己的 exe、源码和资源，另在根目录放项目文件和汇总 `README.txt`；
3. 压缩为 `dist/<输出名>-<版本>.zip`，并校验压缩包内文件与暂存目录完全一致；不一致时删除压缩包并报错。

解压后双击 exe 即可运行，源码在对应目录的 `源码/` 下。这个包只用于运行程序；需要让对方编写 Csay 时，使用安装包，见[发布](34-发布.md)。
