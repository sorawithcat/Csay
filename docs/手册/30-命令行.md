# 命令行

安装后 `csay` 已在 PATH 中。

## 编译与运行

| 命令 | 作用 |
|---|---|
| `csay --version` | 显示编译器版本 |
| `csay 程序.csay` | 检查、生成 C、编译并运行 |
| `csay 程序.csay --fast` | 用随包 TCC 编译，速度快、不优化 |
| `csay 程序.csay --build` | 只生成 exe，不运行 |
| `csay 程序.csay --rebuild` | 忽略缓存，强制重新编译 |
| `csay 程序.csay --check` | 只做语法、名字、成员、参数和类型检查 |
| `csay 程序.csay --debug` | 生成 `#line` 映射并让 C 编译器带调试信息 |
| `csay 程序.csay --format` | 按规范格式原地重写源文件 |

`--check` 不生成 exe。`--format` 只处理命令行指定的文件，不展开 `引` 的依赖；有语法错误时拒绝改写；搭配 `--project` 时逐个目标处理。

## 增量编译

编译前会比较可执行文件、源文件、`引` 引入的文件以及编译器选项。都没有变化时直接复用已有的 exe，不再生成 C 代码或调用 C 编译器；`--build` 会提示“直接使用已有程序”，运行模式会提示“直接运行已有程序”。

需要强制重新生成时加 `--rebuild`。项目依赖各自使用独立的构建目录，也会分别检查自己的缓存。

## 观察编译过程

```bash
csay 程序.csay --check --tokens
csay 程序.csay --check --print
```

- `--tokens` 列出词法单元的行列号、种类和文本；
- `--print` 把语法树还原成规范源码。

两者都不改写源文件。单独使用时，打印完仍会继续编译运行。

## C 编译器

查找顺序：

1. 环境变量 `CSAY_CC`；
2. `clang`；
3. `gcc`；
4. 随包 TCC。

前三个默认加 `-O2`，TCC 不优化。日常迭代用 `--fast`，发布前可用默认编译器。

## 测试

测试文件是普通 `.csay`，用 `断言` 检查：

```csay 测试
断言(1 + 1 == 2, "一加一应等于二");
断言(文本长度("你好") == 2, "文本长度应为 2");
```

断言通过时不输出；条件为假时抛出 `状态异常`，进程以非零码退出。

```bash
csay --test tests
```

测试运行器递归查找目录下的 `.csay` 文件，逐个编译运行，最后汇总通过和失败数量。

## 项目

```bash
csay --project examples/多文件
csay --project examples/多文件 --build
```

`--project` 读取项目目录里的 `项目.csayproj`，按 `entry` 加载入口和 `引` 依赖；产物名取 `output`，未设置时取目录名。项目文件和打包见[项目与打包](31-项目与打包.md)。

## 发布校验

```bash
node tools/发布校验.mjs
```

检查 `package.json` 版本、`--version` 输出、更新日志小节、运行时头文件是否最新，并用同一个样例连续构建两次，确认生成的 C 代码完全一致。校验失败时以非零码退出。
