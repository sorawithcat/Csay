# 异常处理

程序运行时会遇到无法继续的情况：文件不存在、输入格式不对、网络断开。异常处理让程序有机会捕获错误、给出提示，而不是直接崩溃。

## 抛出异常

自己的代码也可以用 `抛出` 主动报错：

```csay 主动抛出
试 {
    抛出 "年龄不能是负数";
} 捕获 (异常 错) {
    打印($"捕获到：{错.信息}");
}
```

`抛出` 后面可以是文本，也可以是一个异常值。程序里更常见的做法是把错误往上抛，让调用方决定怎么处理。

## 异常类型与多捕获

内建了几种异常：`参数异常`、`状态异常`、`文件异常`、`越界异常`、`格式异常`。`异常` 是所有异常的通用类型，可以捕获任意一种。

一个 `试` 可以写多个 `捕获`，从上到下匹配：

```csay 异常类型
试 {
    抛出 文件异常("配置不存在");
} 捕获 (参数异常 错) {
    打印($"参数错误：{错.信息}");
} 捕获 (文件异常 错) {
    打印($"文件错误：{错.类型}");   // 文件错误：文件异常
} 捕获 (异常 错) {
    打印($"其他错误：{错.信息}");
}
```

`错.信息` 是错误文本，`错.类型` 是异常类型名。没有匹配的异常会在执行 `最终` 后继续向外抛出。

## 空异常

异常变量可以赋 `空`，表示“还没有错误”。空异常可以和 `空` 比较，也可以用 `??` 取一个有值的异常：

```csay 空异常
异常 甲 = 空;
异常 乙 = 文件异常("配置不存在");
打印(甲 == 空);           // 真
打印(乙 != 空);           // 真
异常 丙 = 甲 ?? 乙;
打印(丙.信息);            // 配置不存在
```

空异常读取 `.信息` 得到空文本，但不应把它当成真正的错误继续抛出；需要时先用 `== 空` 判断。也可以用 `甲?.信息` 和 `甲?.类型`，为空时同样得到空文本。

几种内建异常都可以直接构造并抛出：

```csay 内建异常
试 {
    抛出 状态异常("状态不对");
} 捕获 (状态异常 错) {
    打印(错.信息);                 // 状态不对
}

试 {
    抛出 越界异常("下标越界");
} 捕获 (越界异常 错) {
    打印(错.类型);                 // 越界异常
}

试 {
    抛出 格式异常("格式不对");
} 捕获 (格式异常 错) {
    打印(错.信息);                 // 格式不对
}
```

## 没有捕获会怎样

如果异常没有被任何 `捕获` 接住，程序会打印“未处理的异常：……”并以非零退出码结束。命令行脚本可以据此判断失败。后面的代码不会再执行。

## 在函数里抛出

函数可以把异常交给调用方处理：

```csay 函数抛出
试 {
    打印(安全相除(10, 2))   // 5
    打印(安全相除(10, 0))   // 抛出异常
} 捕获 (异常 错) {
    打印($"捕获：{错.信息}")
}

长小数 安全相除(整数 甲, 整数 乙) {
    若 (乙 == 0) {
        抛出 "除数不能为 0";
    }
    返回 (甲 + 0.0) / 乙;
}
```

第二个调用抛出的异常被顶层捕获了。异常会沿着调用链向上找最近的一个 `捕获`。

## 什么时候用异常

异常适合**真正的异常情况**，不是普通的流程控制：

- 文件不存在、没有权限；
- 用户输入完全不符合格式；
- 程序内部状态被破坏。

“分数不及格”“列表为空”“找不到记录”这类可预期的情况，用 `若` 或返回值表示更清楚。异常只处理“没法继续正常执行”的问题。
