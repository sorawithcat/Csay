# 未来计划

## 编辑器

- 项目/解决方案文件（`.csayproj`）和一键打包已经落地；后续补项目依赖、排除规则和多目标输出。
- 增加调试适配器（断点、单步、变量查看），而不是只做源码行映射。
- 符号索引从“按工作区扫描”升级为增量索引，支持大型工程。
- 更完整的重命名、格式化范围和文档悬浮提示。

## 编译器与工具链

- 默认编译器的项目配置继续扩展：多入口、资源文件、构建前/后命令。
- 自举编译器目前是单文件。等自举阶段能组织跨文件全局状态后，再按词法、语法、代码生成拆成多个 `.csay` 文件。
- 更完整的增量编译缓存；当前只按内容哈希判断单文件/项目是否过期。

## C# 后端与 CoreCLR

- 新增独立 C# 代码生成器：Csay AST → C# → .NET 程序集。
- 在 C# 后端稳定后，再评估 CoreCLR 热更新宿主：`AssemblyLoadContext`、`MetadataUpdateHandler`、版本切换和状态迁移。
- 这两项都需要独立运行时和测试体系，不是当前 C 后端的一个开关。详见[工具链与运行时](教程/28-工具链与运行时.md)。

## 内存管理

- 继续完善区域分配和 `使用` 的生命周期规则。
- 评估引用计数或可选 GC；当前 C 运行时没有自动垃圾回收，普通堆对象和闭包环境不会自动释放。
- 如果做托管后端，GC 由 CoreCLR 提供，但那是另一条运行时路线。

## 标准库与语言

- 更完整的 JSON 嵌套读写、日期时间解析、正则分组和字符类。
- 标准库继续按文本、文件、时间、数学、集合等模块拆分，避免单个文件无限增长。
- 评估模式匹配、可空类型和更完整的泛型约束；这些都需要先定语义，再改两个编译器。
